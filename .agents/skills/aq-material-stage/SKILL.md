# AQ material stage

1. Require an exact material-authoring controller profile and current AQ state.
2. Preserve stable material IDs and the existing MaterialPlan and ShaderRecipe 0.5 contracts.
3. Keep candidates workflow-owned and within the immutable material-round, build, provider, and promotion budgets.
4. Hand dependency, graph, UV, surface-detail, shadow-compile, and neutral-preview work to the separate closure stage.
5. Never treat a generated image, swatch, or controller completion as promotion authority.

For an explicitly bound reference-fidelity loop, read its exact hypothesis and latest visual findings before material authoring. Preserve the host-selected geometry and correct the named material/surface requirements only. Directional grain needs an explicit material-coordinate/UV direction and physical scale; isotropic noise or added geometry rails do not satisfy that requirement. Run `preflight_directional_material` on an exact staged directional tile and its mapping before spending Blender budget; a local pass is not reference similarity. Prefer existing bounded authoring families and validate their actual rendered appearance. A failed structural feature returns to V0.4 rather than being concealed by surface contrast. Reuse the same shared local and execution budgets, then pass through closure and source-bound paired QA; no human approval is inferred.
