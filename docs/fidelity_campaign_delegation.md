# Finite reference-fidelity campaign delegation

`FidelityCampaignDelegationV01` is an optional disabled-experimental parent of AQ v2
One-Prompt and Approval Envelope. One explicit user decision approves its exact file
SHA-256. Subsequent in-contract scope issuance, candidate preparation, bounded
correction, render, QA, canonical promotion, portable package generation and clean
import use host policy without another user question. The mandate does not approve
future artifact content or record human acceptance.

The parent freezes a clean ActivationSourceManifest/Baseline, ordered references,
independent observation/requirement/camera templates, local-only provider and portable
GLTF output. Each asset declares finite candidate slots. Across all its slots, an
additive epoch permits at most three structural corrections, two shared local/material
corrections, and one strategy switch. Each slot has one data preparation set and at most
two data-only repairs. Historical consumption is retained in full; these numbers are
explicit additions, never reset lifetime counters. Past budgets and terminals remain
unchanged. Changed common source needs a new baseline and parent mandate.

A replacement mandate names the exact previous contract in `supersedes` and carries
forward all prior reserved capacity. The host requires its sessions to be terminal
before approving the replacement. A new delegation ID does not clear consumption.
Separate material identity-split operations have a fixed allowance of zero because
their additional shadow transactions are not priced by this contract.

Each slot uses `FidelityBudgetEpochV01` pricing, including object materializations,
geometry/material builds, three QA units per pipeline round, six separately accounted
closure Blender processes, promotions, one native package repair, controller limits and
the finite native action cap. Aggregate capacity equals the sum of declared slot costs.
Before any child session begins, host policy writes a hash-chained reservation. Reserved
capacity is not refunded after cancellation, failure, early success, restart or rename.
Unused candidate slots remain available only in the original mandate and sequence.
Stop once quality is reached; do not perform unnecessary work to consume the budget.

Authority lives under the configured workspace's `.fidelity_delegations/<id>/`:

- `contract.json` and `decision.json`: immutable mandate and exact user text.
- `scopes/NNNN.json`: host-issued scope, previous hash and aggregate before/after reserve.
- `staging/NNNN/MMMM/`: declared data set paths; JSON/PNG only, no execution authority.
- `preparations/NNNN/MMMM.json`: exact data versions; repairs append, never replace.
- `outcomes/NNNN.json`: host-recomputed terminal and paired visual outcome.

Contract artifact paths resolve relative to the repository. Delegation records and
their artifact paths resolve relative to the configured workspace. Every boundary
rejects escapes, links, missing bytes, mixed receipts and changed hashes. The global
OS guard serializes reservation/admission; reference-wide history guards still apply.
Inherited nonterminal historical sessions retain their exact status and consumption;
the parent neither resumes nor closes them. An execution lock or any subsequent change
to their snapshotted history blocks parent execution. Newly delegated sessions must
reach an exact terminal before their successor can start or another parent supersedes
them. A historical unfinished state is never reclassified as a successful terminal.
`AutonomyBudgetV04` binds the native budget to the parent contract and exact scope.
Legacy `AutonomyBudgetV2/V03`, root/state contracts, Standard and older AQ evidence keep
their original serialization and behavior. No loader creates a delegation retroactively.

The native planner rejects an unbound new AQ job for a governed reference, including
renamed jobs and exhausted or expired mandates. Active session loading, controller
validation, funded geometry/material/closure checks, loop binding, QA reentry and
Approval Envelope policy validation recheck the parent. Observations, requirements,
camera and comparison-lighting selection cannot be weakened. Each routine gate still
requires its exact host eligibility, single-use authorization and receipt; the parent
does not bypass atomic promotion, source freeze, rollback or clean-import validation.

Two repeated same-strategy defects require one funded strategy switch. The next slot
inherits the last attempt's strategy/plateau and any switch on entry consumes that
slot's declared switch reserve. Runtime checks enforce the aggregate reserve as well as
the native session cap. Budget exhaustion preserves best-known evidence and remaining
findings. Technical exceptions do not become requests for user quality approval.

Sequence 1 is a canary. Only its normal terminal, exact delivery/clean-import validation,
source integrity and host-recomputed paired improvement permit the next asset. The
same rule applies in order to the remaining assets. A high IQ score, completed package,
empty unsupported finding list or repeated QA count is insufficient. The comparison
rehashes and re-evaluates both actual render sets and their frozen conditions. No major
unresolved structure defect or regressed feature can count as visual success.

CLI surfaces are `fidelity-delegation-plan`, `-approve`, `-scope`, `-prepare`, `-start`,
`-close`, and `-status`. Mutations require `--experimental-opt-in`; equivalent MCP tools
are project-allowlisted. `-start` uses the AQ skill adapter and returns an existing exact
session after interruption instead of replanning. A partially published native boundary
fails closed and retains its reservation for technical recovery; it grants no new slot.
Execution remains inside the current Codex task, with no repository-spawned task or
continuation after app exit.

The policy ledger contributes **zero** human beauty, package and Activation acceptances.
Those decisions remain separate, exact user records. Contract/source/reference/budget/
provider/destination expansion requires a new concrete parent proposal and question;
an in-contract successor scope or routine technical recovery does not. Existing
per-scope approval paths remain valid for non-delegated historical/legacy work.
